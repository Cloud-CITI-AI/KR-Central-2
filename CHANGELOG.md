# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).
Releases are prepared by release-please from Conventional Commits.

## [Unreleased]

### Added

- Monorepo scaffold (pnpm 11, Node 24, TypeScript strict, ESLint, Prettier, Vitest, Stryker, Playwright, commitlint, lefthook).
- Specifications: product spec, data model, design tokens, ADRs 0001–0014, work package plan.
- `@kr/workflow`: the 10 stages and 46 checkpoints as typed data, pure progress/next-action/alert rules, Perth date helpers.
- `@kr/contracts`: zod API schemas, route registry, permissions matrix and generated OpenAPI 3.1 document.
- `@kr/db`: initial Postgres 17 schema, migration runner, database roles, operations queue and audit helper.
- `@kr/design-tokens`: prototype colours (light and dark), typography and base styles.
- Service skeletons (API, worker, web), CI, security scanning, release and Railway deploy workflows.
- `services/ops` skeleton for the Railway `migrate` (pre-migration backup + migrations, sole holder of the migrator role) and nightly `backup` services.
- Prototype reference (code, CSS, blank-demo screenshots) under `docs/reference/prototype/`.
- Work-package plan as data (`docs/plan/work-packages.json`) with render, check and issue-creation scripts; review decisions in `docs/plan/DECISIONS_LOG.md`.

### Changed

- Backup: the `backup` cron connects as the new read-only `tracker_backup` role through `BACKUP_DATABASE_URL`; only the `migrate` service holds `MIGRATION_DATABASE_URL` (ADR-0008). Re-run the database bootstrap with `TRACKER_BACKUP_PASSWORD` to create the role before deploying.
- Deploys are called from the release workflow after images are attested, run services in order (clamav → migrate → api → worker → web → backup) and verify attestations of private GHCR images.
- Schema: OIDC flows are bound to the browser (`auth_flows.browser_binding_hash`), evidence and source files are constrained to their job, job numbers are checked (R15), sessions record `acrs`, files record `scan_attempts`.
- API config: spec rate limits and 100 KB JSON body limit, `HOST` (`::`), `TRUST_PROXY_HOPS` default 1, identity-provider host pinned in staging/production, MFA evidence via `amr` or `acrs`.
- CI: every workspace package gated, per-layer coverage for diff coverage, mutation limited to each package's mutate globs, Prettier check, pinned scanners.
- Web first-load JavaScript (gzip): `/jobs/[jobId]` 253.8 to 217.2 KB, `/` 239.5 to 199.4 KB, `/admin/*` 237.8 to 199.9 KB. The browser API client uses the schema-free `@kr/contracts/routes-table` (generated by `pnpm openapi:generate`) and `@kr/contracts/capabilities`; forms that validate with the contract schemas load on demand. The routes stay on their lowered budget waivers.
- Web first-load JavaScript (gzip), every route now within the 170 KB budget with no waiver: `/jobs/[jobId]` 217.2 to 165.6 KB, `/` 199.4 to 164.5 KB, `/admin/*` 199.9 to 164.4 KB, `/sign-in`, `/sign-in-error`, `/signed-out` and `/_not-found` 146.0 KB (the root 404 had pulled the signed-in shell into every route). The tracker body, dashboard content, admin pages and viewer dialog are lazy chunks; the signed-in 404 is the `(app)` group's (`(app)/[...notFound]`); `@kr/workflow` is marked `sideEffects: false`. `BUDGET_WAIVERS` is empty and the public routes cannot be waived; the all-routes first-load budget goes 400 to 170 KB and the lazy-JS budget 240 to 305 KB (the same code, moved).

### Fixed

- Sign-in: a guest whose identity provider did not verify the email (`xms_edov=false`) can no longer reach a job through an access grant added after their first sign-in, or through a grant bound while the email was verified. Grants bind only to accounts whose latest sign-in was verified (`users.email_verified`, migration 0002); an unverified sign-in of an account holding grants is refused and its sessions ended.
- Admin sign-in with `ADMIN_MFA_EVIDENCE=acrs` now asks Entra for the authentication context (`claims` on the authorize request), so the ID token carries `acrs` and admins pass the MFA gate.
- Configuration: the api, worker and ops refuse to start in production without an explicit `APP_ENV` (it used to default to `local`, switching every guardrail off), and in staging/production refuse `.env.example` placeholder secrets and `REQUIRE_MFA_FOR_ADMIN=false`. An empty optional variable (a pasted `.env.example`) now counts as unset instead of failing startup.
- Database: `tracker_app` can only read `tracker.schema_migrations` (ADR-0007).
- Conformance Notification: an upload to 4.2 starts its conformance read once the scan passes (or at once when scanning is disabled); the first-page readers no longer apply the 60-page cap.
- Local stack (`docker compose --profile stack up`): the S3 mock has a health check and `migrate` waits for it, so a cold start no longer fails with `ECONNREFUSED` on the pre-migration backup.
- Job edits no longer get a false 412 ("This item was changed by someone else") after another person ticks, decides or marks paid a checkpoint or edits a condition: the job's `version` now versions only the job's own fields, and checkpoint and condition writes only move its updated time.
- Clearing the conformed date also clears the WAPC outcome date (R10), so the countdown, the "Changed by hand" hint and the dashboard's outcome alerts no longer linger.
- Two people editing different fields of one condition, checkpoint or job (a KR comment and a client comment, a status and a note, two dates) no longer get a 412 that throws the second person's typed text away: a stale `If-Match` saves when none of the fields it changes was changed since, and is a 412 only for a real same-field conflict.
- A save refused as stale (412) keeps what the person typed (a condition's KR or client comment, a checkpoint's KR note, job details and dates) on the reloaded item instead of emptying the field.
- Web: text typed into a KR comment, a condition comment or a job note when the session ends is kept and put back after signing in again, instead of being discarded by the redirect to sign-in.
- Web: a status change that can't be saved says so for a lost connection and for a rate limit (429), instead of "Reload the page and try again".
- Web: the dashboard shows one banner, announced to screen readers, when the jobs or counts can't be loaded or refreshed, with the connectivity wording, the request id and "may be out of date" when cached cards are showing.
- API contract: `startConditionsExtraction` and `startConformanceReading` declare the required `Idempotency-Key` header (OpenAPI regenerated); the web client now sends it for conformance readings.
- The email viewer shows the parsed message (Subject/From/To/Cc/Date, a rule, the body) for .eml, Outlook .msg and pasted emails instead of the raw MIME source or "can't be previewed", and every email dialog has "Download original". `EmailMeta` gains a nullable `bodyText` (null until the file is scanned clean or skipped).
- "Open in new tab" and any other button-styled link use the ink colour, not the browser's link blue.
- A missing, archived, forbidden or malformed job answers HTTP 404 inside the one signed-in shell (one header, one h1, one main) instead of nesting a second shell with a 200; unknown routes show the signed-in shell too.
- Page titles name the page: "Dashboard", "<job number> – <address>" and "Page not found".
- The audit trail's Job column shows the job number (`AuditEvent.jobNumber`, also for archived jobs) in the accent link colour instead of a UUID prefix.
- Admin pages have a Dashboard button, the header logo links to the dashboard, and the Users and Audit trail tabs use the ink colour.
- API: a NUL character (U+0000) in any text field, query or path parameter is refused with a 400 naming the field instead of a 500 (Postgres 22021); dates outside 1900-01-01..2199-12-31 and malformed multipart uploads are 400s too.
- API: when object storage is unreachable, uploads, downloads and the job package answer 503 with `Retry-After` and the new problem type `urn:kr:problem:storage-unavailable` ("File storage is temporarily unavailable. Try again shortly.") instead of a 500.
- Files: text is accepted only under a `.txt`, `.csv` or `.md` name (415 otherwise) and files already stored with another extension are downloaded and zipped as `.txt`; an 8-bit `.eml` in a non-UTF-8 charset is accepted; browser-escaped quotes and line breaks in upload names are decoded.
- Job package: a file whose object is missing from the bucket is skipped and listed under "FILES NOT INCLUDED" in Job summary.txt instead of cutting the zip short, and a package that cannot be produced is no longer audited.
- Alerts: "expires in 1 day", "due in 1 day" and "1 condition needs its agency checked" (singular wording); `isIsoDate` handles years below 100.
- Web: secondary text meets WCAG 2.2 AA contrast (4.5:1) on every surface: `--ink-2`, `--ink-3` and `--grey-ink` are darker in the light theme and `--ink-3` lighter in the dark theme (recorded in `DESIGN_TOKENS.md`); axe now runs without the contrast carve-outs for the greys.
- Web: the PDF viewer draws pages in browsers without `Map.prototype.getOrInsertComputed` (browsers from before about early 2026, iOS Safari included): the page and the pdf.js worker (now `/pdfjs/pdf.worker.polyfilled.mjs`) install the two ES2026 methods; the e2e harness no longer injects a polyfill.
- Web: the PDF viewer's pages can be scrolled with the keyboard (a focusable "Pages of <file>" region with a visible focus ring).
- Web: the tracker's stage bars are level-2 headings (the outline is stages, then checkpoints), and each condition's evidence file input has its own name ("… (condition 2)").
- Web: dashboard cards stop animating their progress bars under reduced motion, and a client name with no spaces wraps instead of making the page scroll sideways.
- Web: the status key panel is laid out like the prototype (heading rule across the panel, rows spread over its height).
- Web: the tracker page holds its place while the job loads (no layout shift of the footer, CLS 0.654 to 0.000 on the reference profile) and Expand all is cheaper (stage bodies are not rendered again and appear a stage per frame, INP proxy p75 0.69 s to 0.18 s); the tracker's CLS waiver is gone, its INP ceiling is 0.3 s and its LCP ceiling 4.9 s (the header photo, outside the tracker).
- API: the dashboard list, facets and job picker no longer read every checkpoint state and condition of every job on every request. At 2,000 jobs (PRODUCT_SPEC section 14) the k6 smoke measured p95 2.3-4.3 s against the 300 ms target; unchanged jobs now reuse their summary (keyed by a per-job fingerprint of its states and conditions, its WAPC dates, the day and whether the viewer may see the fee proposal), and the requests of one viewer that arrive together share one read. Results are identical, the fee proposal decision still never reaches a viewer without `fee_proposal.view`, and a write shows in the next response.
- Web: the tracker's job picker no longer pages the whole job list (about 21 requests at 2,000 jobs) when a tracker loads; it fetches the list when the picker is first hovered, focused or clicked.
- Load test: the k6 smoke (`pnpm --filter @kr/web exec playwright test -c perf/k6.config.ts`) now seeds the designed scale of 2,000 jobs with realistic checkpoint states and conditions, and times the job picker's list request, so a regression of this size fails CI.
- A date outside 1900-2199 can no longer make a job unreadable: the document readers ignore years outside the range (a reference number such as `12/05/1066`, a sentence about 2999), the worker never writes an out-of-range approval, expiry, conformed or outcome date (it treats the reading as not found), and `PATCH /v1/jobs/{id}` answers 400 on `conformedDate` when conformed + 90 days would pass 2199-12-31 instead of committing a row whose `GET` is a permanent 500.
- Migration 0003: job dates are constrained to 1900-01-01..2199-12-31 (`jobs_dates_in_range`); rows that already held an out-of-range approval, expiry, conformed or outcome date are repaired by setting it to NULL (a nulled conformed date also clears its method, source file, stamp text and outcome date), with the job version bumped and one `job.dates_repaired` audit row naming the old values, so those jobs open again.
- A decline comment made only of invisible characters (U+200B-U+200D, U+2060, U+FEFF, soft hyphen ...) is refused with a 400 like a blank one (R14): `isBlank()` in `@kr/contracts` and `is_blank_text()` in the database (migration 0003, which also replaces `checkpoint_states_decline_needs_comment`; an existing declined decision with such a comment gets the visible text "(No reason was recorded)" and a `checkpoint.decision_repaired` audit row).

- API: a path parameter over 100 characters (`GET /v1/jobs/<600 characters>`) and a malformed percent-encoding in the path answer `application/problem+json` with the request id (414 `urn:kr:problem:uri-too-long`, and 400 validation) instead of Fastify's raw JSON body that echoed the path; `maxParamLength` is set explicitly in `app.ts`.
- Downloads and package zips: a stored file whose extension is not one of its sniffed kind's own (a PDF stored as `report.exe`, `invoice.pdf.lnk` or `noext`, an image as `photo.scr`) is served as `report.exe.pdf`, `photo.scr.jpg` ... (the stored display name is unchanged), so a download can never be something the recipient's machine runs; `servedFileName(name, kind, contentType)` now covers every kind.
- Files whose virus scan failed: the tracker said "Couldn't be checked for viruses – remove it and upload it again" after the first failure although the hourly sweep re-scans up to `SCAN_ERROR_MAX_RETRIES` times, so people re-uploaded duplicates. `FileMeta.scanRetriesExhausted` (migration 0004, `files.scan_retries_exhausted`, written by the worker with the failure) is true only once no re-scan is left; until then document rows, email rows and the viewer say "Still being checked for viruses…".
- Conditions extraction and conformed-date reading: a second start request (another Idempotency-Key, a second tab, a double click after a reload) while one of the same kind is queued or running for the job is answered `409` ("The Decision Letter is already being read. Wait for it to finish."; "The conformed date is already being read. ...") instead of queueing a duplicate; `GET /v1/jobs/{id}` carries `activeOperations` ([{id, type, status}]) so the tracker can resume polling `GET /v1/operations/{id}` after a reload.
- Tracker: after a reload the 5.0 "Extract conditions" and 4.2 "Read conformed date" controls follow a reading that `JobDetail.activeOperations` lists (button disabled with "Reading Decision Letter…", "Reading the conformed date…") and show its result, instead of offering the buttons again with nothing running; a refused duplicate start shows the server's "already being read" text and picks that reading up.
- Accessibility (WCAG 2.4.3): after "Extract conditions from Decision Letter" the focus moves to the result message ("1 condition extracted", or the reason it could not run) instead of being lost to the page body when the pressed button is disabled; a reading resumed after a reload and a person who has moved on elsewhere keep their focus.
- Starting a conditions extraction or conformance reading from a PDF whose virus scan failed but will still be retried answers 409 "... is still being checked for viruses. Try again in a moment." (file-not-ready) instead of "remove it and upload it again", which is now said only once the automatic re-scans are used up.
- Web: the pressed dashboard filter chip's count, the orange links on the conditions checklist (new `--accent-ink` token) and the amber countdown's unit labels meet 4.5:1 contrast in both themes (recorded in `DESIGN_TOKENS.md`); the axe states now include a cleared condition and the amber countdown and tolerate no known contrast pair.
- Web: Save as PDF and print keep the header (with its logo and title), the progress ring, the bars, the stage tracks and the status colours (`print-color-adjust: exact`) in the light palette whatever the theme, and hide the dashboard's status filter, type chips and search.
- Web: the header's hero photo is a 48 KB AVIF (WebP fallback, 16 KB at phone width) preloaded from the root layout instead of a 276 KB JPEG found after the CSS; LCP on the reference profile drops from 3.9 to 4.4 s to 1.7 to 1.9 s and the LCP waivers are removed.
- Web: a very long unbroken file name no longer makes the tracker scroll sideways on a phone, an excluded stage's label no longer overlaps its name at 390 px, the audit trail's filters line up, and the document viewer shows a small image at its own size instead of enlarging it.

# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).
Releases are prepared by release-please from Conventional Commits.

## [Unreleased]

### Added

- Monorepo scaffold (pnpm 11, Node 24, TypeScript strict, ESLint, Prettier, Vitest, Stryker, Playwright, commitlint, lefthook).
- Specifications: product spec, data model, design tokens, ADRs 0001–0014, work package plan.
- `@kr/workflow`: the 10 stages and 46 checkpoints as typed data, pure progress/next-action/alert rules, Perth date helpers.
- `@kr/contracts`: zod API schemas, route registry, permissions matrix and generated OpenAPI 3.1 document.
- `@kr/db`: initial Postgres 17 schema, migration runner, database roles, operations queue and audit helper.
- `@kr/design-tokens`: prototype colours (light and dark), typography and base styles.
- Service skeletons (API, worker, web), CI, security scanning, release and Railway deploy workflows.
- `services/ops` skeleton for the Railway `migrate` (pre-migration backup + migrations, sole holder of the migrator role) and nightly `backup` services.
- Prototype reference (code, CSS, blank-demo screenshots) under `docs/reference/prototype/`.
- Work-package plan as data (`docs/plan/work-packages.json`) with render, check and issue-creation scripts; review decisions in `docs/plan/DECISIONS_LOG.md`.

### Changed

- Deploys are called from the release workflow after images are attested, run services in order (clamav → migrate → api → worker → web → backup) and verify attestations of private GHCR images.
- Schema: OIDC flows are bound to the browser (`auth_flows.browser_binding_hash`), evidence and source files are constrained to their job, job numbers are checked (R15), sessions record `acrs`, files record `scan_attempts`.
- API config: spec rate limits and 100 KB JSON body limit, `HOST` (`::`), `TRUST_PROXY_HOPS` default 1, identity-provider host pinned in staging/production, MFA evidence via `amr` or `acrs`.
- CI: every workspace package gated, per-layer coverage for diff coverage, mutation limited to each package's mutate globs, Prettier check, pinned scanners.
- Web first-load JavaScript (gzip): `/jobs/[jobId]` 253.8 to 217.2 KB, `/` 239.5 to 199.4 KB, `/admin/*` 237.8 to 199.9 KB. The browser API client uses the schema-free `@kr/contracts/routes-table` (generated by `pnpm openapi:generate`) and `@kr/contracts/capabilities`; forms that validate with the contract schemas load on demand. The routes stay on their lowered budget waivers.

### Fixed

- Local stack (`docker compose --profile stack up`): the S3 mock has a health check and `migrate` waits for it, so a cold start no longer fails with `ECONNREFUSED` on the pre-migration backup.
- Job edits no longer get a false 412 ("This item was changed by someone else") after another person ticks, decides or marks paid a checkpoint or edits a condition: the job's `version` now versions only the job's own fields, and checkpoint and condition writes only move its updated time.
- Clearing the conformed date also clears the WAPC outcome date (R10), so the countdown, the "Changed by hand" hint and the dashboard's outcome alerts no longer linger.
- Two people editing different fields of one condition, checkpoint or job (a KR comment and a client comment, a status and a note, two dates) no longer get a 412 that throws the second person's typed text away: a stale `If-Match` saves when none of the fields it changes was changed since, and is a 412 only for a real same-field conflict.
- A save refused as stale (412) keeps what the person typed (a condition's KR or client comment, a checkpoint's KR note, job details and dates) on the reloaded item instead of emptying the field.
- Web: text typed into a KR comment, a condition comment or a job note when the session ends is kept and put back after signing in again, instead of being discarded by the redirect to sign-in.
- Web: a status change that can't be saved says so for a lost connection and for a rate limit (429), instead of "Reload the page and try again".
- Web: the dashboard shows one banner, announced to screen readers, when the jobs or counts can't be loaded or refreshed, with the connectivity wording, the request id and "may be out of date" when cached cards are showing.
- API contract: `startConditionsExtraction` and `startConformanceReading` declare the required `Idempotency-Key` header (OpenAPI regenerated); the web client now sends it for conformance readings.
